Browser analysis

How SceneDetect runs locally in the browser

The workbench is a static GitHub Pages application. It uses the browser for media decoding and Rust compiled to WebAssembly for scene-detection semantics. The selected video is not uploaded to a server.

Local media stays local

Selecting a video creates a browser-local object URL. The page reads and decodes that file on the current device. No application server receives the media, and the static site does not need an upload endpoint to perform detection.

The browser owns decode and sampling

Browsers expose decoded video frames rather than FFmpeg's native frame pipeline. The workbench samples those frames at the configured analysis rate, scales them to the configured maximum dimension, converts the current frame to RGB pixels, and passes the resulting sample to WebAssembly.

The sampling rate therefore trades analysis cost against timing resolution. Increasing it gives the detector more temporal detail; decreasing it reduces the number of frames that must be decoded and processed.

Rust owns scene-detection semantics

Detector defaults, scene scores, thresholds, adaptive windows, fade handling, minimum scene length, scene construction, boundary-review status, and exports come from the compiled scenedetect-core implementation. The browser layer supplies sampled pixels and presents the results; it does not reimplement those decisions in JavaScript.

Sampling follows presented video frames

When available, the media adapter waits for requestVideoFrameCallback() after a seek so canvas reads follow a frame actually presented by the browser. It records the presented media time and rejects a decreasing timeline before pixels enter the Rust detection session. Browsers without that API use a conservative animation-frame fallback.

Visual review is downstream of detection

Before/after thumbnails are decoded separately for inspection. They can help review an accepted, suppressed, or near-miss candidate, but preview generation never feeds pixels back into the detection session or changes Rust-owned candidate decisions.

What this browser path does not claim

Browser presentation synchronization improves fidelity, but it does not claim native FFmpeg frame-exact decoding or variable-frame-rate timestamp parity. Detection still operates on the configured sampled browser timeline. Native media parity remains a separate concern from the WebAssembly detector itself.
