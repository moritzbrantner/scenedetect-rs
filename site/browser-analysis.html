Browser analysis

How SceneDetect runs locally in the browser

The workbench is a static GitHub Pages application. It uses the browser for media decode and Rust compiled to WebAssembly for scene-detection semantics. The selected video is not uploaded to a server.

Local media stays local

Selecting a video creates a browser-local object URL. The page reads and decodes that file on the current device. No application server receives the media, and the static site does not need an upload endpoint to perform detection.

The browser owns decode and sampling

The main browser thread owns the <video> element, seek/presentation synchronization, canvas reads, and sampling cadence. RGB buffers are transferred to a module worker, so the WebAssembly session and Rust export generation do not run on the UI thread.

Rust owns scene-detection semantics

Detector defaults, scene scores, thresholds, adaptive windows, fade handling, minimum scene length, scene construction, boundary-review status, and detector exports come from scenedetect-core. The browser supplies sampled pixels and presents results; it does not reimplement detector decisions.

Sampling follows presented video frames

When available, the media adapter waits for requestVideoFrameCallback() after a seek so canvas reads follow a frame actually presented by the browser. The presented media timestamp travels with the RGB sample through the WebAssembly session and returns in the result, so the timeline can retain both sampled-frame indexes and browser media time.

Human review is separate evidence

Manual cuts, rejected candidates, and scene merges are stored as browser-owned review decisions. They derive a reviewed scene list without mutating the immutable Rust detector result. Saved run comparisons likewise compare detector boundaries without changing them.

What this browser path does not claim

Browser presentation timestamps improve timeline fidelity, but the workbench does not claim native FFmpeg frame-exact decoding or complete variable-frame-rate parity. It preserves the media times of the browser-presented samples it actually analyzed. Native decode parity remains a separate concern from the WebAssembly detector itself.
