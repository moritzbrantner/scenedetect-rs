Rust scene detection · CLI + WebAssembly

Detect once. Reuse the evidence.

scenedetect-rs is a Rust reimplementation and expansion of PySceneDetect. Its native workflow treats reusable Detection Stats as the canonical result of scene detection, while compatibility commands remain available as a verified parity seam.

Browser boundary

Selected media stays local. The browser owns decode and sampling; Rust compiled to WebAssembly owns Detector semantics. The browser surface does not pretend to be native FFmpeg decode.

Read how browser analysis works

Native workflow

Detection is a reusable data boundary

Run a Detector once to produce canonical Detection Stats, then derive the views and formats a caller needs. Exact Media Time is a separate timing-aware projection rather than hidden mutation of Detector truth.

01 Detect

Decode frames and write input.scenedetect.json.

02 Inspect or render

Reuse matching Detection Stats for scenes, stats, HTML, and boundary review.

03 Project exact timing when needed

Render a Scene Timeline with rational Media Time endpoints.

Quick start

A small CLI surface around explicit artifacts

Content, Adaptive, Threshold, Histogram, and Perceptual Hash Detectors are available in the native workflow and through the current PySceneDetect v0.7 compatibility surface. 

scenedetect-rs detect content -i input.mp4
scenedetect-rs render scenes -i input.mp4
scenedetect-rs render stats -i input.mp4 --csv
scenedetect-rs render timeline -i input.mp4

Compatibility seam

PySceneDetect-compatible commands remain available

The parity surface currently covers detect-content, detect-adaptive, detect-threshold, detect-hist, and detect-hash. Supported behavior is projected from the machine-readable capability manifest and checked against required parity cases. 

scenedetect-rs -i input.mp4 --output out detect-content list-scenes
scenedetect-rs -i input.mp4 detect-adaptive --threshold 3 list-scenes
